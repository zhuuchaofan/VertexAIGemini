# 真实 Vertex 调用验证计划

状态：**仅计划，未执行。** 没有写任何调用代码，没有使用任何凭据。执行前需要你逐项确认第 7 节的清单。

## 1. 为什么要做

本地假上游已经证明了客户端侧的行为（一次调用一个请求、取消令牌让枚举立即结束、取消后连接多开 2 秒以及修复后的关闭延迟）。**它不能证明真实 Google 服务的任何行为**，包括：取消后服务端是否停止生成、是否按已生成部分计量、响应里的用量字段是否真的被填充、Vertex 端点用的是 HTTP/1.1 还是 HTTP/2。这些只能用真实调用测。

两件事要分开测，因为它们回答不同的问题，也有不同的成本和风险：

| | 实验 A：取消 | 实验 B：完整结束并获取用量 |
|---|---|---|
| 回答 | 取消令牌之后，连接是否立刻关闭？取消前能不能拿到用量？取消后还能看到什么？ | 一次完整、短小的调用结束后，用量、结束原因、响应元数据分别是什么？是否真的只发了 1 个请求？ |
| 对应的方案条目 | 2.7 停止、2.3.4 取消后关闭连接、用量标记为 `estimate` 的依据 | 3.1 的 `usage`、`finishReason`、`providerCalls` 字段 |

## 3. 实验 A：取消

**目的：** 在真实服务上观察「取消」的客户端可见行为，并确认取消前能拿到什么用量信息。

| 项 | 值 |
|---|---|
| 最多调用次数 | **1**（一次流式生成） |
| 提示词 | 「请依次列出从 1 到 200 的阿拉伯数字，每行一个，不要输出其他任何内容。」（目的是让输出足够长，保证取消发生在生成中途） |
| 输出上限 | `MaxOutputTokens = 1024`（硬上限，即使取消失败，一次调用最多产生 1024 个输出 token，包含思考 token） |
| 超时 | 单次 60 秒 |
| 取消时机 | 收到第 3 个含文本的分片后立即取消；若 10 秒内没收到足够分片，也取消并如实记录「未能在中途取消」 |
| 使用的客户端 | 与生产完全相同：`GeminiHttpOptions.Create()` + `GeminiHttpOptions.CreateClientOptions()`（`ResponseDrainTimeout = 0`） |

**记录并报告（不下结论的项明确写「无法判断」）：**

1. 协商的 HTTP 版本，以及请求头里是否带了认证（只记录有无，不记录值）。
2. 取消令牌到枚举结束的耗时；取消令牌到底层连接关闭的耗时（客户端可观察的部分）。
3. 取消前收到的每个分片是否带 `UsageMetadata`，以及其中的字段值。
4. 取消之后是否还有任何迟到的数据到达（应当没有）。
5. **取消后服务端是否继续生成、是否计费：从客户端无法判断。** 可选的旁证：几分钟后在 Cloud Monitoring 的 Vertex AI 指标里看这段时间内该模型的 token 计数，但指标有延迟、是聚合值，**只能作为旁证，不作结论**。计费数据通常有数小时延迟，不在本次范围。
6. 第二次执行：不执行。只有一次。

**这个实验改变什么：** 如果取消后连接确实在毫秒级关闭，方案 2.7 的「停止」链路在真实服务上得到客户端侧确认；如果出现意外（例如连接不关闭、HTTP/2 下行为不同），需要调整处理器配置；用量标记 `estimate` 的做法保持不变，因为取消时拿不到权威用量。

## 4. 实验 B：完整结束并获取用量

**目的：** 拿到一次完整调用的真实用量和元数据，核对我们的字段设计。

| 项 | 值 |
|---|---|
| 最多调用次数 | **1**（一次流式生成，读到流结束） |
| 提示词 | 「只回复两个字母：OK」 |
| 输出上限 | `MaxOutputTokens = 256`（给低档思考留出余量，仍是很小的硬上限） |
| 超时 | 单次 60 秒 |
| 使用的客户端 | 同实验 A |

**记录并报告：**

1. 用量：`PromptTokenCount`、`CandidatesTokenCount`、`ThoughtsTokenCount`、`TotalTokenCount`，以及哪个分片带了它们（最后一个分片还是每个分片）。
2. `FinishReason`、`ModelVersion`、`ResponseId`、是否有 `ModelStatus`。
3. 首个文本分片耗时、全程耗时（作为「浏览器侧与模型侧耗时分开标注」的参考值，仅此一次，不当作基准）。
4. 供应商请求数：**必须恰好为 1**，这是对「SDK 在真实服务上也不隐式重试」的验证（前提是这次没有碰到瞬时错误；若碰到，记录并停止，不重试）。
5. 与我们的 `estimate`（字符数除以 4）对比，只用来说明估算与真实值的差距量级，不用来校准。

**这个实验改变什么：** 决定 `meta.usage` 与 `runs.usage` 能否直接取自供应商（`source: "provider"`），还是仍需标记为估算；决定检视器里「用量」一栏哪些字段有真实值、哪些显示「未知」。

## 5. 成本

- 两次调用的输出被硬性限制在 1024 + 256 个 token 以内，输入很短（几十个 token）。
- **我无法核实 `gemini-3.8-flash` 当前的价格**，所以不在这里给出金额。请你在执行前对照官方价格页面确认；按上面的硬上限，单次实验的成本是有界的，量级应当极小，但具体数字以你查到的价格为准。
- 没有任何会放大成本的路径：不重试、不循环、不并发，总请求数由处理器层计数并强制 ≤ 2。

## 6. 中止条件

出现下面任何一种情况立即停止，不再发起更多请求，并把日志交给你：

- 认证失败或权限不足（403、401）；
- 任何 4xx 或 5xx（不重试）；
- 请求数计数达到 2 之后又出现第 3 个；
- 总时长超过 120 秒；
- 输出里出现了提示词之外的、看起来像是别的上下文的内容。
